# UT 覆盖率统计规则

**版本**: v1.1
**创建日期**: 2026-06-01
**更新日期**: 2026-06-01

## 核心原则

分层统计，聚焦核心逻辑。数据访问层（DAO/Repository）不需要很高的 UT 覆盖率，应剔除该层后重新计算总体覆盖率。

## 为什么数据访问层不需要高覆盖率

### 数据访问层代码特点

```
典型数据访问函数：
├── 输入验证（5%）
├── SQL/查询构建逻辑（15%）
├── 数据库执行（70%）← 外部依赖，Mock 测试价值低
└── 结果映射（10%）
```

### Mock 的局限性

- ❌ 无法验证 SQL 语句正确性
- ❌ 无法验证事务完整性
- ❌ 无法验证连接池管理
- ❌ 无法验证数据一致性

### 行业最佳实践

- ✅ 数据访问层 UT 覆盖率：20-30%（使用 Mock）
- ⭐ 数据访问层真实性验证应该在 SIT 集成测试
- ⭐ 重点：Logic 层（业务逻辑）+ Package 层（工具函数）

## 覆盖率类型

**Statement Coverage（语句覆盖率）**：
- 定义：统计被执行的代码语句比例
- 计算：`语句覆盖率 = (被执行的语句数 / 总语句数) × 100%`

## 分层统计目标

| 测试层级 | 覆盖率目标 | 统计方法 | 验证方法 |
|---------|-----------|---------|---------|
| **Logic 层 UT** | **≥80%** | 计入总体统计 | Mock 测试 |
| **Package 层 UT** | **≥60%** | 计入总体统计 | Mock 测试 |
| **数据访问层 UT** | **20-30%** | ❌ 不计入总体统计 | Mock 测试 |
| **数据访问层集成测试** | **60-80%** | 单独统计（SIT） | 真实数据库 |

### 术语映射

通用术语与项目实际目录的对应关系：

| 通用术语 | Go 项目 | Vue 项目 | 覆盖率目标 |
|---------|---------|---------|-----------|
| Logic 层 | `internal/service/` | `src/views/` + `src/stores/` | ≥80% |
| Handler 层 | `internal/handler/` | — | ≥60% |
| 数据访问层 | `internal/repository/` | `src/api/` | 20-30%（SIT 验证） |
| Package 层 | `pkg/` | `src/utils/` | ≥60% |
| Model 层 | `internal/model/` | `src/types/` | 不统计（纯数据结构） |

## 统计方法

### Step 1：生成完整覆盖率报告

```bash
# Go 后端
cd backend
go test ./... -coverprofile=coverage.out -covermode=count
go tool cover -func coverage.out | grep "total:"

# Vue 前端
cd frontend
npx vitest run --coverage
# 输出到 test_reports/frontend/coverage/
```

### Step 2：剔除数据访问层后重新计算

```bash
# Go 后端：过滤 repository 包
cd backend
go tool cover -func coverage.out | \
  grep "dev-loop/" | \
  grep -v "/repository/" | \
  grep -v "/mocks/" | \
  grep -v "/model/"
```

### Step 3：生成报告

```markdown
# UT 语句覆盖率报告（剔除数据访问层）

| 指标 | 目标 | 实际 | 状态 |
|------|------|------|------|
| **总体（剔除数据访问层）** | 70% | **{actual}%** | ✅/❌ |
| **Logic 层** | 80% | **{logic}%** | ✅/❌ |
| **Package 层** | 60% | **{pkg}%** | ✅/❌ |
| **数据访问层** | 20-30% | **{dao}%** | ✅/❌ |
```

## 行业对标

| 层级 | 行业标准 | 来源 |
|------|---------|------|
| **Logic 层 UT** | 80%+ | Google、Martin Fowler |
| **Package 层 UT** | 60%+ | 通用标准 |
| **数据访问层 UT** | 20-30% | 阿里巴巴（集成测试 80%+） |

## 最佳实践

### ✅ DO

1. 分层统计，Logic 层计入总体，数据访问层单独统计
2. 使用 Mock 测试数据访问层，验证 Logic 层调用的正确性
3. 在 SIT 集成测试中验证数据访问层（真实数据库）

### ❌ DON'T

1. 不要追求数据访问层高覆盖率（60%+ 没有必要）
2. 不要只看总体覆盖率（包含数据访问层会偏低）
3. 不要忽视 SIT 集成测试（数据访问层真实性验证在 SIT）
